## 已确定的边界

- Mac 控制端使用 Swift；Android 使用 React Native。
- 多个用户相互隔离，每人可管理多台执行 Mac；任务分别选择引擎、模型和电脑。
- Codex/Grok 的凭据、模型会话和执行循环均在用户 Mac 上；模型请求从 Mac 直连供应商。
- 服务器只承担鉴权、设备连接、持久化、确定性调度、记忆服务、画面中继及成本汇总。
- 主助理在用户指定 Mac 上运行；所有合适的电脑离线时仅接收排队，不生成模型回复。
- 云端记忆经鉴权工具按需检索；设备、引擎与记忆服务解耦。
- 首版浏览器画面按需低频刷新；完整桌面和视频为后续扩展。

## 本轮确定的实现选择

- 云端采用模块化单体，独立 API/Gateway 和后台 Job 进程，共用代码与 PostgreSQL；暂不拆微服务。
- Node.js 受支持 LTS、TypeScript、Fastify 5；实施时锁定实测版本，不在设计阶段声称某版本已完成兼容。
- PostgreSQL 18；SQL migration 为数据定义依据，应用使用参数化查询。持久队列、outbox 和用量账本先放同库，记忆复用已有 agent-recall，不新增 pgvector 依赖。
- 原生登录走 OIDC + PKCE，执行设备用独立密钥认证，Run 使用短期授权；模型密钥不进入这些协议。
- 初版使用邀请开通作为可调整的默认值；OIDC 服务与 Android 推送提供方需在上线前选定。
- 跨引擎/设备切换创建新 Run，通过结构化检查点交接；不迁移隐藏推理或供应商原生会话。
- 成本按设备上报做个人观测，区分供应商返回、估算和未知；不实现平台钱包或代付结算。

## 阅读时的约定

“必须”表示实现和验收约束；“建议值”表示可配置的初始值，需实测；“待验证”不得当作上线能力。示例域名与 ID 为虚构数据。技术文档中的 SQL/TypeScript 片段用于说明设计，不是已部署实现。

## 本轮核验

- 从本机 Codex 0.170.0 生成非实验 app-server schema，核对启动、补充、中断及用量通知的数据结构；尚未验证真实业务执行。
- 首批设备消息 schema 通过 Draft 2020-12 结构校验，5 个有效样例通过，10 个无效样例被拒绝；已启用 UUID/时间格式校验。
- 已解析文档中的 JSON 示例并检查本地文件链接；未执行数据库 migration、真机 UI、通知和故障恢复测试，因为本轮尚无对应业务实现。
