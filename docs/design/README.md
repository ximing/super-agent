## 第二版：Mac 原生工作台方向

[打开第二版](workbench-native.html) · [助理截图](workbench-native-overview.png) · [任务工作区截图](workbench-native-tasks.png) · [验收窗口](workbench-native-review.png)

用户认可第一版的整体结构，反馈视觉过于像 Web。第二版保留信息架构，重新设计窗口层次与交互方式。

- 合并标题与操作到统一工具栏，移除网页面包屑、首页大问候语和全宽紫色交办按钮。常用动作保留新建、刷新、搜索和检查器开关。
- 侧栏改为 31 pt 左右的紧凑导航行，选中底色使用中性灰紫；新任务也可通过 ⌘N 创建。
- 主区直接展示对话与工作过程。执行方案改为轻量的步骤大纲，状态用文字和小圆点表达，减少卡片、胶囊和阴影。
- 右栏改为检查器：任务信息/活动分段切换，标签—值属性、相关工作、交付和按需浏览器入口。侧栏与检查器可拖拽调整宽度，也可收起。
- 任务区改为「列表 + 固定详情」：选择持续高亮，点击任务或用上下方向键选择后，右侧直接更新内容；详情不再弹出全局窗口。任务列表宽度可调整。
- 引擎/电脑选择采用输入区旁的 Popover。新建与验收使用有明确开始和结束的 Sheet；交付材料使用预览窗口，返回验收时保留已填内容。

第二版的设计原则是「工作内容为主、系统容器安静」。配色为白色内容 `#FFFFFF`、工具栏 `#F6F5F7`、侧栏 `#EEEDF0`、主文字 `#29292E`、辅助文字 `#77757F`、操作强调 `#6257C6`；继续使用 SF Pro / 苹方。取消大块紫色背景，优先用系统选中态、分隔线和紧凑布局表达层次。

与第一版对比自查后，进一步移除了常驻浏览器缩略图和卡片式任务方案，把更多宽度与高度留给实际工作。没有通过全屏毛玻璃或大面积渐变模拟原生质感。

Swift 落地对应 `NavigationSplitView`、原生 `.toolbar`、`HSplitView` 或 inspector、原生 List 的选择绑定、分段 Picker、`.popover` 与 `.sheet`。HTML 中的红黄绿窗口按钮和材质只是说明位置；实际客户端由系统绘制，图标优先使用 SF Symbols。具体组件可用性以 `Package.swift` 的部署目标和当前 Swift SDK 为准。

设计参考：[Apple 工具栏规范](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[侧栏规范](https://developer.apple.com/design/human-interface-guidelines/sidebars)。第二版仍为离线 HTML 示例，数据与操作不连接真实服务。

第二版验证：在 Chrome 中检查 1440 × 900、1260 × 840、1040 × 680、390 × 844 的对话布局，无整页横向溢出，输入区保持可见。验证七项导航、侧栏收起/恢复、检查器页签和收起、分栏调整事件与键盘宽度调整、Popover 执行配置、草稿保留、列表方向键选择、详情页签、任务暂停/继续、创建与搜索、验收条件校验及预览返回后的表单保留。浏览器未记录运行错误，内嵌 JavaScript 语法检查通过。本轮仅修改设计稿与说明，没有修改 Swift 应用。

## Swift 原生实现同步

[本轮原生 UI 验收、修复与截图](native-acceptance/README.md)

2026-11-19，`apps/macos` 已按第二版重构真实 SwiftUI 工作台。外壳使用 `NavigationSplitView` 与系统 `.toolbar`；工作区、任务列表和检查器使用可拖调的 `HSplitView`。任务选择由列表与检查器共享，普通任务详情留在工作区，新建和验收使用 Sheet。引擎、电脑和模型采用原生紧凑 `Menu`，与设计的 Popover 入口保持同等就近配置语义；主助理电脑仍在电脑页独立配置。

助理和逐任务补充草稿由 `WorkspaceModel` 持有，配置、导航与检查器切换不会清空。交付材料预览叠加在验收 Sheet 上，关闭预览不销毁验收表单状态。父子归属、前置依赖、待验收、已验收、结果待核对和未知费用继续沿用既有业务模型与 API，没有改动实现契约。

原生截图使用显式 `--demo-screenshot` 隔离 fixtures，不恢复真实会话或启动云端轮询。Sheet 由应用窗口与 Sheet 窗口合成到同一 PNG，避免只截到背景。macOS 14 SDK 会对该调试截图辅助 API 报弃用警告；它不参与正常业务界面或执行链路。

## 视觉方向

以个人 Mac 助理的「交办、推进、核对」为主线，采用左侧导航、中间工作内容、右侧任务上下文的布局。所有内容左对齐；对话主列限制宽度，右栏可以收起。避免把首页变成统计面板，优先展示正在推进的工作和需要用户处理的事项。

| Token | 值 | 用途 |
| --- | --- | --- |
| Canvas | `#F7F8FB` | 主工作区 |
| Sidebar | `#F0F1F6` | 侧栏与结构层次 |
| Surface | `#FFFFFF` | 输入、交付和任务容器 |
| Ink | `#292B38` | 正文与标题 |
| Iris | `#6B59D3` | 主操作、选中、进行中 |
| Divider | `#E9EAF1` | 内容分组 |

状态另使用绿色表示已验收、琥珀色表示待核对，均辅以文字。字体使用 macOS 系统字体：英文 SF Pro、中文苹方；标题 24–28 pt，正文 12–13 pt，辅助信息 10–11 pt。Swift 落地优先用语义化字体并复核实际屏幕可读性。卡片圆角 12–14 pt，按钮 7–8 pt，输入容器 13 pt；尽量用分隔与留白表达层级，只有弹窗等悬浮元素使用明显阴影。

```text
┌─────────────┬─────────────────────────────────┐
│             │ 原生工具栏 / 当前页面 / 待处理  │
│ 搜索与交办  ├──────────────────────┬──────────┤
│             │ 欢迎与待验收提示     │ 当前任务 │
│ 功能导航    │                      │          │
│             │ 主助理对话           │ 浏览画面 │
│ 最近工作    │ 方案与分步进展       │          │
│             │                      │ 最近交付 │
│ 设备与账户  │ 输入与紧凑执行配置   │          │
└─────────────┴──────────────────────┴──────────┘
```

初版自查后保留的重点：对话中的执行方案是主视觉；不加大型统计卡、装饰渐变或循环动效；设备/引擎设置从大 Picker 收进紧凑入口。示例日期、画面采集时间、设备名称和费用均用于表达布局，不代表真实服务状态。右栏的分段条仅示意方案阶段，不表示已加载任务之外的完整完成率。

## SwiftUI 对应实现

HTML 用于快速评审；不把 WebView、React 或 Web 组件库作为原生客户端的实现基础。

| 设计稿元素 | SwiftUI 落地方式 |
| --- | --- |
| 侧栏、主内容、上下文栏 | `NavigationSplitView` 保留主导航；detail 内用 `HSplitView` / `HStack` 组织工作内容与可收起 inspector |
| 系统标题栏与窗口按钮 | 使用真实系统窗口装饰和 `.toolbar`，不重画 HTML 中的示意窗口按钮 |
| 工作台搜索 | `.searchable` 或独立搜索 Sheet；保留 ⌘K |
| 输入与发送 | `TextEditor`、自定义容器、⌘Return；保留普通 Return 换行 |
| 引擎、电脑、模型 | `Menu` / `Popover` 与原生 `Picker`；只显示设备实际提供的模型与引擎 |
| 任务列表 | 原生 `List` / `Table`，保持选择与键盘导航 |
| 任务详情 | 主区 detail 或 inspector 内的「概览 / 执行过程 / 交付物」切换；HTML 暂用 Sheet 演示 |
| 新建、验收与补充要求 | `.sheet` + 原生 `Form`；显示明确的作用范围 |
| 通知与轻提示 | 行内状态与 SwiftUI overlay，实际系统通知沿用现有通知模块 |
| 图标 | HTML 内嵌 Lucide；Swift 优先 SF Symbols（如 `bubble.left.and.bubble.right`、`checklist`、`desktopcomputer`） |

主应用仍以现有最小窗口 1040 × 680、默认窗口 1260 × 840 为落地基准。HTML 另适配窄窗口：先隐藏上下文栏，再把导航折叠为抽屉。这只帮助评审布局，不表示更改现有 Swift 窗口限制或重构 Android。

## 可以体验的交互

- 七项主导航与任务状态筛选。
- 任务详情三个页签、暂停/继续、任务内补充要求。
- 新建示例任务、主助理消息、紧凑执行配置、附件名称预览。
- 待回答、逐条验收、选择证据、填写说明、退回补充、交付预览。
- ⌘K 搜索、⌘Return 发送、Escape 关闭、键盘焦点及对话框焦点限制。
- 设备、记忆、定时关注与用量页面的视觉示意。

不混淆执行结束与验收完成；验收通过要求全部标准勾选、证据选择和说明。前置依赖需验收完成后放行；实际图关系、版本冲突和证据合法性仍由现有服务契约校验，不由设计稿模拟成真实能力。定时关注仅提醒并准备目标，确认后执行。订阅金额未知单列，不显示为零。
