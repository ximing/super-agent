# 技术实施计划与验收门槛

日期：2026-11-18。依据：[技术设计](technical-design.md)、[协议](protocol-v1.md)、[PRD](../tasks/prd-personal-super-agent.md)。本轮交付设计与契约，不代表下列系统已实现。阶段按依赖排序，不承诺未经评估的工期。

## 1. 当前产物与实施原则

- 已整理模块边界、数据模型、API 目录、状态机、派发/补传语义、引擎与设备切换、记忆、费用与部署方案。
- 已提供首批设备消息 schema 与样例，校验结果在实际执行后记录。
- 已检查本机 Codex 0.170.0 非实验协议中的启动、补充、中断及用量数据结构；未运行真实浏览器业务任务验证。
- 各阶段先完成最小闭环，再开放更高并发或原生 Subagent 优化。
- 多用户隔离从第一批 migration 开始，不能在单用户原型完成后再补；模型 Key 不上传从最初适配器就执行。
- 任何阶段的 UI/任务进度区分“服务端已收到”“设备已接受”“正在运行”“已静止/已完成”。

## 2. P0：运行时与环境验证

交付 `spikes/` 下可重放的最小验证程序与记录，输出目标版本、能力清单、限制和样本证据；本阶段不开发完整 UI。

| 编号 | 验证 | 退出条件 |
| --- | --- | --- |
| S-01 | Codex stdio 握手、开始、steer、提问/答案、中断、resume | 事件能归因到原生 thread/turn；停止回执与在途工具可区分 |
| S-02 | Codex 原生 Subagent 与计量 | 确认继承工具、停止传播、父子用量口径；不满足则先关闭原生优化 |
| S-03 | Grok 本地 Key 解析与 API 工具循环 | 本机直连，完成工具请求/执行/结果回传、错误与费用样本 |
| S-04 | CSI task session、截图、焦点与人工操作 | 目标 tab 不串，截图/动作串行；明确 iframe、验证码、系统弹窗限制 |
| S-05 | 原生后台运行 | Mac 关闭应用窗口后节点继续；休眠/锁屏/重启后状态如实显示 |
| S-06 | 通知 | 选定 Android 手机杀进程/国内网络与 Mac APNs 配置可达；记录不支持条件 |
| S-07 | 引擎与设备切换 | 用无副作用样本演示检查点重建，旧运行静止前不能放行新操作 |

真实公司网站的三个工作样本由用户后续提供；在此之前可用受控样本验证协议，但不能据此宣称业务成功率。不得为了测试擅自发布、发送或修改真实业务数据。

## 3. P1：协议、身份、租户与设备骨架

依赖 P0 的协议结论，具体开发可先进行不依赖运行时的部分。

交付：

- monorepo 工作区、协议生成与版本检查、CI 基础检查。
- 选定 OIDC 提供方，完成 native PKCE、会话交换、刷新、退出和撤销。
- PostgreSQL migration、RLS、组合外键、连接池租户事务封装。
- 配对、公钥挑战、设备 token、能力上报、heartbeat 与 connection generation。
- 本产品凭据/服务器地址配置与模型配置分离；节点只报告引擎 readiness。
- Swift/TS 生成类型以及有效/无效兼容样例。

验收：用户 A/B 各配两台设备；A 不能读 B 的设备、记忆、任务、文件和事件；正文篡改 tenant、猜测 ID、连接池复用、批量查询、后台查询、运维接口都不越权。撤销会话/设备后既有订阅失效。API 与日志不存在模型 Key/Token 传输路径。

## 4. P2：持久任务闭环与恢复

依赖 P1。先用 deterministic FakeRuntime 验证调度，不消耗供应商费用。

交付：

- 对话、任务目标与 scope 来源、Run、步骤、问题答案与检查点。
- Postgres 公平队列、outbox、命令过期与 accept、Run/资源租约。
- 节点 SQLite inbox/outbox、producer sequence、重传、ACK、重连 reconcile。
- 主助理持久 inbox、plan/item 去重和原子提交；创建 Task 后、收到回复前崩溃也不会重复派活。
- 用户默认引擎/电脑、单任务覆盖、主助理租约与手动接任。
- bootstrap/补读游标、Task/Run 状态机与标准错误。

验收：

- 两个用户、四台节点连接，在同一用户两台电脑并行执行独立任务，跨用户不串。
- 固定电脑离线时等待，不自动派其他电脑；命令过期未接受与已接受后失联区别处理。
- 在 DB 提交前后、命令接受前后、ACK 丢失时注入故障，重启后无重复 Runtime 启动。
- 晚提交事务不会被客户端 stream cursor 漏过；快照与增量组合能恢复所有活跃对象。
- 问题在两端同时回答只有一个版本生效；同一个主助理租约不会有双写回复。

## 5. P3：Codex/Grok 受管执行

依赖 P2 和 P0。实际模型请求只从用户节点发出。

交付：

- 两个 RuntimeAdapter、统一工具注册表、run ticket、工具参数校验与审计。
- Codex 本机登录复用与项目级受管工具配置，不覆盖全局配置。
- Grok 本机 Key 配置契约、请求循环、退避、输出/工具次数边界与本地会话持久化。
- 主助理异步启动 Worker、结果事件路由、范围内子任务与统一交付。
- 引擎/设备切换动作、检查点导出、依赖文件转移和重新观测。

验收：Codex 与 Grok 各完成同一受控任务；主助理在 Worker 忙碌时仍能回复并派第二项工作。旧 Worker 及受管后代停止后才交接资源。未知提交结果进入核对，不因切换/重试重复操作。检查抓包、配置和日志确认服务器没有供应商请求与模型凭据。

## 6. P4：浏览器过程查看与 Mac 日常使用闭环

依赖 P3。保留单设备一个浏览器操作通道。

交付：

- SwiftUI 对话、任务列表/详情、设备选择、问题处理、引擎切换。
- CSI BrowserActor、操作时间线、关键截图与任务文件。
- 独立媒体通道、按需 JPEG、视口版本、查看/控制不同权限。
- 人工接管、明确继续、原生通知与安装/配对/登录状态向导。

验收：真实 Mac 上关闭窗口后任务继续；用户看画面、暂停、操作、继续全过程不争抢焦点；慢图像网络不拖延停止请求。过时画面输入被拒绝，控制 lease 超时后保持暂停。三个工作样本逐个记录人工介入、异常、用量与实际回执。

## 7. P5：云端记忆、主动规则与成本大盘

依赖 P3，界面依赖 P4。计量从 P3 就采集，不能到此阶段才开始补记。

交付：

- memory search/read/propose、教学、来源与版本、纠错/删除/活跃任务失效。
- 复用已部署 agent-recall 的中文检索、内容与版本；每用户独立绑定，不新增 embedding 或向量库部署依赖。
- 一类已授权观察规则、定时触发、去重、静默与摘要通知。
- usage records/revisions、费率版本、日聚合、个人与受权运维成本查询。
- Run 额度预留、Token/时间边界、个人月预算、未知费用与覆盖率。
- Swift 成本概览、趋势、按设备/引擎/任务下钻与预算提醒。

验收：更正知识后新任务使用新版本；跨用户检索零暴露；同一用户其他设备可复用网站档案。费用对重复、流式累计、失败重试、Subagent 和切换处理正确；Codex 订阅未知金额不显示为零。并发预留不能透支可分配额度，但界面如实说明在途费用不能绝对封顶。

## 8. P6：Android 与发布前加固

Android 在 P1 后可按契约实现登录、列表等独立页面，完整端到端验收依赖 P3–P5。

交付：

- React Native 对话、任务、设备、问题、记忆和成本页；协议/错误语义与 Swift 一致。
- 安全会话存储、后台推送、深链、前后台恢复、截图缩放与输入映射。
- 多设备会话撤销、弱网/断网恢复、成本导出与数据保留设置。
- OTel/结构化日志、告警、容量/越权检查、备份恢复演练、部署与节点升级回滚。

验收：目标 Android 真机覆盖杀进程、通知跳转、重复点击、屏幕旋转和长时断网。20 用户/30 在线设备/20 Run/5 画面订阅作为首轮压测配置，实际结果决定可开放容量，不能只依赖本地功能测试。恢复演练验证任务、记忆、对象和用量可恢复，恢复后不盲目重跑副作用。

## 9. 必须有的跨阶段验证矩阵

| 类别 | 重点用例 | 通过判据 |
| --- | --- | --- |
| 隔离 | ID 替换、检索、订阅、导出、连接池、签名 URL | 拒绝越权，不进入他人上下文 |
| 幂等 | 重复消息/命令/答案、ACK 丢失、同 ID 不同 hash | 同操作不重复，冲突明确 |
| 提交 | 网站成功后回执丢失、断网后重连、引擎切换 | 核对真实结果，无盲目重复提交 |
| 竞争 | 两端回答、Coordinator 接任、浏览器争用、预算预留 | 单个有效写入者，其他显式等待 |
| 计量 | 流式累计、重试、费用修订、缓存输入、原生子 Agent | 总额来源可追溯且不重复 |
| 离线 | 单电脑/全电脑离线、过期租约、丢 SQLite | 明确等待/核对，不伪造继续执行 |
| UI | Swift/RN 真机、弱网、过期帧、后台通知 | 进度语义一致，可回答和恢复 |
| 升级 | 协议当前/上一版本、DB 扩展迁移、节点降级 | 不误解命令，恢复路径可演练 |

仅对有状态协议、隔离和故障恢复编写必要测试；普通文案和低影响布局不写镜像实现的测试。实际业务成功依赖真实样本，不用“模型有返回”作为完成判据。

## 10. 实施前默认值与待确认事项

可直接采用的起步默认值：一用户一个 tenant；一设备一个浏览器操作通道；指定设备优先；主助理默认手动接任；无 Key 上传；暂无 embedding 时关键词模式；未知费用单列；共享基础设施与个人模型费用分开。

以下需要在对应阶段确定，独立部分可以先做：

1. 三个首发工作场景、目标网站、完成判据与允许行动范围。
2. 首批用户/设备/并发规模、服务器与对象存储、域名和 OIDC 服务。
3. Mac 最低系统版本、节点与 Swift 应用签名/分发方式。
4. Android 品牌和主要网络条件，推送通道及隐私展示要求。
5. embedding 部署与数据许可、记忆资料是否可进入服务器和各模型服务。
6. 注册邀请/开放策略、运维成本角色、文件/日志/备份保留期。

下一实施起点为 P0 的双引擎/浏览器验证与 P1 的协议/隔离基础，验证结论回填到本方案，再固定可开放能力。
